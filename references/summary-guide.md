# 划重点摘要写作规范（summaries/<ID>.md）

给批量写摘要的人（或模型）用。目标是「读摘要就能抓住全篇关键」，且能通过
`--check-summaries --strict` 交付门禁。**数字准确性是第一红线。**

## 一、文件骨架

```markdown
# 划重点｜《原文完整标题》

<!-- summary:begin -->

> **一句话结论**：……（最核心的判断，1-2 句）

- **作者**：<作者昵称>（雪球专栏）｜**发布**：YYYY-MM-DD HH:MM（北京时间）
- **原文**：https://xueqiu.com/<UID>/<ID>
- **归档**：YYYY-MM-DD ｜**本地全文**：`articles/<ID>.md`
- **性质**：作者个人观点整理；文中行情、财务、估值与概率数字均为作者自行整理，**非一手来源，需核实原文**

---

## 1｜（按文章实际结构自拟小标题）

（表格 / 列表 / 引用块，见下）

---

**原文**：https://xueqiu.com/<UID>/<ID> ｜**本地全文**：`articles/<ID>.md`

> **免责声明**：以上内容基于公开数据和量化分析，仅供参考，不构成投资建议。市场有风险，投资需谨慎。任何投资决策应结合个人风险承受能力、资金状况和投资目标独立判断，必要时咨询持牌专业机构。过往表现不预示未来收益。

<!-- summary:end -->
```

- `<!-- source-md5: ... -->` / `<!-- reviewed: ... -->` **不要手写**，由
  `--check-summaries --stamp` 自动插到 `summary:begin` 之前。
- `<!-- summary:begin -->` 与 `<!-- summary:end -->` 必须成对，否则阅读册不显示卡片。
- H1 标题阅读册自己给，正文里从 `##` 起；渲染器支持表格、标题、引用、有序/无序列表、粗体、行内代码、链接，其余普通段落按 `<p>` 处理。

## 二、硬性字段（写错任一都会判硬错误或待复核）

| 项 | 要求 |
|---|---|
| 文件名 | `summaries/<文章ID>.md`，ID 必须存在于 `metadata.json`，否则摘要永远不显示 |
| 原文链接 | 必须与 metadata 里该篇 `url` **逐字一致**，不要带 `?` 参数、不要短链、不要补 `/`；全文只出现这一个雪球链接 |
| 发布时间 | 必须与 metadata 里该篇 `published` 逐字一致，格式 `YYYY-MM-DD HH:MM`，写在「发布：」之后 12 个字符内 |
| 本地全文 | 只能写 `articles/<本篇ID>.md`，出现别篇 ID 判硬错误 |
| 免责声明 | 必须同时含「免责声明」和「不构成投资建议」 |
| 合规标注 | 正文出现带单位数字（% / 倍 / 点 / 成 / 亿 / 万 / bp / 个月 / 美元 / 元）时，摘要内必须含「非一手」和「需核实原文」；出现「概率」二字时，必须含「主观判断」或「非测算」 |

> 写之前先从 `metadata.json` 取该篇的 `title` / `published` / `url`，直接复制，不要凭记忆。

## 三、数字红线（strict 门禁最容易卡这里）

复查会把摘要里每个带单位数字拿回原文核对：在原文找不到就判「待复核」，strict 模式下
直接失败。**所以：**

1. **只用原文出现的数字**，逐字照抄。不要自己换算（原文 0.203 就不要写 20.3%）、
   不要四舍五入、不要补全、不要写原文没有的数字（哪怕「常识上合理」）。
2. **范围写法照抄原文**：原文是「13 到 18%」就写「13 到 18%」，不要只写「18%」，
   也不要改成「13%~18%」。两种写法复查都会展开两端各自核对。
3. **单位要跟原文一致**：原文「25bp」可写「25bp」或「25 个基点」；原文「4 个月」
   不要写「120 天」。
4. 会被自动忽略、可以放心用的：章节号（`## 1｜`）、列表序号、年份（2015）、
   日期（2026-10-29、6/25）、时间（10:55）、行内代码（`articles/123.md`）、URL。
5. **禁止为了「显得具体」而造数字**。宁可写定性描述（「明显回落」「历史高位」），
   也不要编一个精确值。

写完后跑：

```bash
python <SKILL_DIR>/scripts/archive.py --root "<归档目录>" --check-summaries          # 看「摘要复查报告.md」逐条数字溯源
python <SKILL_DIR>/scripts/archive.py --root "<归档目录>" --check-summaries --strict  # 交付门禁：待复核项也会失败
```

报告里「❌ 未找到」的就是抄错或原文没写的数字，回去改；「◐ 仅数字命中」是数字对
但单位/口径不同，核对上下文后决定是否保留。

## 四、组织方式（划重点，不是复述）

不要求每篇都套同一模板。先判断文章类型，再挑合适的模块，**一般 4-7 个块**：

- **市场研判类**（有数据/点位/仓位）：一句话结论 → 核心判断表（分维度/分情景）
  → 关键数字（3-6 个，均照抄原文）→ 方法论/自我修正 → 情景概率（标注主观）
  → 操作纪律/仓位表 → 成立前提与反面证据 → 免责声明。
- **体系/认知类**（少数字、多论述）：一句话结论 → 核心论点分层 → 关键概念对照表
  → 可操作的方法/步骤 → 常见误区 → 作者强调的前提 → 免责声明。
- **产业链/个股类**：一句话结论 → 产业链环节表 → 各环节的玩家与格局 → 关键数字
  → 风险与证伪条件 → 免责声明。
- **自传/随笔类**：一句话结论 → 生平/主张要点 → 思想主线 → 可提炼的原则 → 免责声明。

模块标题用 `## 1｜` `## 2｜` 编号，表格优先——「看不到关键」通常是因为没做结构化。

## 五、写完一篇的自查清单

- [ ] 一句话结论抓住了作者真正的主张，不是泛泛概括
- [ ] 标题、发布、原文链接、本地路径都与 metadata 逐字一致
- [ ] 所有带单位数字都能在原文找到，范围写法与单位照抄
- [ ] 概率处标注了「主观判断/非测算」，行情数字处标注了「非一手/需核实原文」
- [ ] 免责声明完整，`<!-- summary:begin/end -->` 成对
- [ ] 没有把工具说明、归档说明之类的文字写进摘要正文
