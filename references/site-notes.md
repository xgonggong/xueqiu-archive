# 雪球站点笔记与踩坑清单

本文件记录「凭常识猜不到、每次都会重踩」的技术细节。排查接口变化、限流、正文异常或归档质量问题时读取。

**内容索引**：接口清单 → 限流规律 → 字段限制 → 踩坑清单（1–25）→ 交付前校验 → 阅读册加工层 → 合规与数据边界。按需跳到对应小节，不必通读。

## 接口清单（2026-11 实测）

| 用途 | 地址 | 要点 |
|---|---|---|
| 用户时间线 | `https://xueqiu.com/statuses/user_timeline.json?user_id=<UID>&page=N&count=20` | 按时间倒序，筛 `is_column` 且 `title` 非空即为专栏长文；`count=100` 返回 400，保持 20 |
| 文章页 | `https://xueqiu.com/<UID>/<ID>` | 正文在 `window.SNOWMAN_STATUS.text`（原始 HTML，含配图） |
| 单篇接口 | `https://api.xueqiu.com/statuses/show.json?id=<ID>` | 同样返回完整 `text` 与配图；**须先访问一次主域拿 cookie** |
| 专栏列表页 | `https://xueqiu.com/<UID>/column` | 动态渲染，静态抓取只有第一页；不要用它的条数当作全量 |
| 镜像页 | `https://ai.xueqiu.com/<UID>/<ID>` | 仅用于诊断；不要从中提取配图，见下方踩坑 |

时间线页数取决于作者发文量（实测某活跃作者约需 78–90 页才覆盖全部历史）。脚本按「扫到空页为止」翻页，默认上限 90 页，可用 `--max-pages` 调整；但**该参数只用于首次冒烟测试**，已有归档跑增量时会被强制忽略。每页之间保留 0.12s 以上间隔。

## 限流规律

- 主域连续约 10 次文章页请求会触发 WAF frequency limit，返回非预期内容。
- `api.xueqiu.com` 子域不受该限流影响，是可靠降级通道；限流会随时间解除。
- 抓取循环保留 0.4–0.8s 间隔；降级后不要再回切主域重试。
- 单篇接口需要先 `warm()` 访问主域建立 cookie，否则可能失败。

## 字段限制

- 时间线 `view_count` 恒为 0，**阅读量只在专栏列表页展示**，公开接口拿不到，不要试图批量补齐。
- `edited_at` 可用于轻量改文检测；更早文章可能落在前 30 页之外，用单篇接口按 ID 补齐即可覆盖全量。
- `text` 中的股票代码是 `<a href="https://xueqiu.com/S/...">` 外链，归档后保留即可，不联网也能显示文字。
- 图片 URL 域名 `xqimg.imedao.com`；表情图不走该域名，保留外链。

## 踩坑清单

1. **`<template>.content` 是 DocumentFragment，没有 `innerHTML`**。用 `tpl.content.innerHTML` 注入正文会渲染成字符串 `undefined`。DocumentFragment 只有 `textContent` / `cloneNode`。最稳的做法是正文静态内嵌为 `<section>`，JS 只切换 `.active`；脚本被禁时全文仍按顺序可读。用 `tpl.innerHTML` 取字符串也可，但静态内嵌更抗环境差异。
2. **镜像页补图会污染原文**。页面外围 DOM 里常有站点广告图（实测一张蓝色「安全、可信、低费率」图被当成正文配图塞进 22 篇文章，md5 完全相同）。宁可缺图也不要猜配图。已删除镜像补图与「挂回本地已有图片」两段逻辑；`--verify` 会对下载图片做 md5 查重，同一内容出现在多个文件名下即报错。
3. **工具生成的说明文字绝不写进正文**。早期注入的「【归档说明】以下配图由镜像页补抓…」污染了 12 篇 md 与 HTML 快照。要标注就用 HTML 注释；自检把该字符串视为污染。
4. **跨通道比对正文要先归一化**：去空白、去 Markdown 图片引用后再比较，否则排版差异会误报「作者改文」。排版重建用 `--rebuild`，不生成 diff。
5. **正文来源要统一**。若一部分文章只有 Markdown、另一部分有原始 HTML，阅读册排版会不一致。保证每篇都落盘 `<ID>.source.html`。
6. **CSV 被 Excel / 编辑器占用会 `PermissionError`**：批量写文件要捕获并跳过，不能中断整轮同步。
7. **HTML 模板用 Python `%` 格式化时**，CSS 里的 `100%` 必须写成 `100%%`；生成后检查有无残留 `%(...)s`。改用 token 替换可彻底规避。
8. **图片要本地化**：CDN 外链会失效；文中图片按出现顺序命名 `<ID>_N.<ext>`，阅读册用相对路径 `images/...` 引用。只拷 `index.html` 不带 `images/` 会丢图，但正文文字仍完整。
9. **增量同步会抹掉归档专有字段**（最隐蔽的一个）。`scan_timeline()` 每轮从接口重建 dict，不带 `source` / `fetched_at` / `body_chars` / `images` / `topic` / `reads`；直接写回 `metadata.json` 会让抓取通道、抓取时间戳、`--reads-file` 注入的阅读量全部丢失，`目录.csv` 阅读量列被清空，作者名还可能被占位符覆盖。必须在写回前用旧元数据合并这些字段（**仅当新值为空时继承**），并从已有归档恢复 `uid` / `author` / `reads`。自检里对 `source` 缺失只提示、不判失败，避免旧归档被误判为损坏。
10. **限量页数会截断已有索引**。对已有归档误用 `--max-pages 3`，同步后 `metadata.json` / `目录.csv` / `index.html` 只剩最近几篇；更隐蔽的是接口中途失败提前 `break` 也会腰斩。对策：已有归档忽略小 `--max-pages` 强制全量扫描，且扫描结果少于已有条目时把旧条目补回去（作者删帖时本地快照仍应保留）。
11. **不要把某个真实作者 UID 设为默认值**。漏传 `--uid` 会静默抓错作者、把文章写进错误目录。正确做法：首次归档必须提供（否则报错退出）；已有归档从 `metadata.json` 恢复；显式 UID 与归档记录冲突时直接报错。`--author` 同理从归档恢复，避免每轮增量把昵称改回占位符。
12. **主题规则别绑死单一作者**。默认关键词若全是某人的标题用词，换作者后筛选框几乎只剩「其他」。用通用投资类词汇打底，允许 `--topics-file` 定制；已归档文章的 `topic` 字段保持不变，调整规则不会让整库分类突变。
13. **摘要复查要按「能自动判定 / 只能人判断」分层**。高发四类错：数字抄错、把别篇数据写进来、作者改文后摘要没跟上、改了 md 却没重建阅读册。自动层做结构标记、ID/原文链接/发布时间/本地路径一致性、免责声明、正文 md5 基线、`index.html` 卡片同步；可疑层做数字溯源并附原文上下文。**不要把「数字未命中」直接判失败**——作者常写换算值（「还差 216 点」是两个点位相减的结果）；更不要把「数字命中」说成「理解正确」。默认待复核清单 + 可选 `--strict` 门禁，兼顾两者。
14. **数字归一化决定复查噪音**。原文常写 `13%~18%`、`3到5个月`、`25个基点`，摘要写 `13 到 18%`、`3 到 5 个月`、`25bp`。摘要和原文必须做**同样的范围展开**（给两端都补上单位）并支持单位等价（`bp`↔`个基点`、`点`↔`个点`），否则一半数字会被误报成「仅数字命中」。章节号、年份、月份、时间、长 ID 要先剔除，否则低辨识度数字刷屏、真正可疑的项被淹没。
15. **基线 hash 不能用整个 md 文件**。文件头带每次抓取的时间戳，`--rebuild` 会让 33 篇全变、把「作者改文」误报一遍。用「去头部 + 去空白 + 去图片引用后的正文」算 md5。基线写成 `<!-- source-md5: ... -->` 放在 `<!-- summary:begin -->` 之前：注释行会被转换器跳过，不影响阅读册渲染。
16. **补回旧条目必须按 ID 差集，不能按总数判断**。原逻辑是「本轮扫到的篇数 < 已有篇数」才把旧条目补回；作者删 1 篇同时发 1 篇新文时总数不变，被删文章会静默从 `metadata.json` / `目录.csv` / `index.html` 消失（md 文件还在磁盘上，但阅读册看不到了）。同理，接口中断只扫到部分但新增文把总数撑住时也会漏。改为 `set(old) - set(new)` 逐个补回并标 `remote_missing`，不猜测是删帖还是接口问题。**抓取失败时也要把本地快照喂回 `bodies`**，否则全量模式下该篇仍会从阅读册消失。
17. **占位符会伪装成正常正文**。`len(text_html) < 100` 判不了：站点删除提示页带完整 HTML 模板，长度轻松过百；作者也可能把长文改成两三百字的「本文已修订」说明。现在改成**纯相对判断**（见 18）：完全没有文字、命中删除类关键词且相对上一版明显变短、或相对上一版缩到不足一半，任一命中就沿用本地快照；相对阈值不设「旧正文至少 500 字」的门槛（实测 780 字短文换成 288 字说明时，30% 阈值恰好放行，改成「不足一半」才覆盖）。**`--rebuild` 最危险**：它原本不生成旧版快照，占位符一旦通过就会直接抹掉原文，所以覆盖前必须存 `.pre-rebuild.md`。所有拦截都可用 `--accept-shrink` 显式放行。
18. **绝对字数阈值会误伤短文，且新旧口径必须一致**。早期 `body_quality()` 用「不足 100 / 200 字」「关键词命中且不足 600 字」拦截，`--verify` 还把「正文 < 500 字」判失败；雪球本身就有几百字的正常短文，一刀切会把它们当成占位符。现已全部去掉，只留「一个字都没有」的空内容底线（抓取通道与自检同样只判空、不判短）。更要命的是口径：新正文用 HTML 纯文本计数、旧正文用 Markdown 计数时，Markdown 里的 `[文字](URL)`、图片引用会让旧值虚高——实测同一篇**未变化**的文章被算成 13260 → 10157 字，在 `--accept-shrink` 下凭空多出一份「删除前快照」。比较底本一律取上一份 `<ID>.source.html` 的原始 HTML，两侧都过 `plain()`，同文重抓比值≈1；没有 HTML 快照时才用 Markdown 折算并主动丢掉链接 URL。
19. **「作者主动删除」要留下可找回的最后一版**。默认保护路径不覆盖，主 md 就是线上消失前的最后一版完整全文，把 `last_full_snapshot` 指向它即可。唯一会覆盖的是 `--accept-shrink`：覆盖前额外写 `_snapshots/<ID>_<时间>.before-delete.md`，把相对路径写进 `metadata.json`（`last_full_snapshot` + `shrink_note`）、`目录.csv` 的「线上状态」列，并在阅读册篇头渲染成可点开的链接；`--verify` 校验该文件存在且非空。否则快照只是在磁盘上躺着，下轮同步以占位符为基线后旧版就再难定位。这两个字段必须进 `ARCHIVE_FIELDS`，否则增量同步重建 dict 时会丢。

20. **参数组合必须显式校验，不能靠「忽略」**。最危险的是 `--stamp` 单独使用：原本只打印一行「本次忽略」，随后一路走到 `warm()` + 扫时间线 + 逐篇重抓 + 覆盖 md / 原始 HTML / `metadata.json` / `index.html`——一个看似只读的参数触发了整轮写盘与联网。现在 `validate_options()` 对「`--stamp` 缺 `--check-summaries`」「多个检查模式并存」「`--missing-only` + `--rebuild`」直接 `p.error()` 退出 2，其余无效组合打印警告。另一个隐蔽点：`--root` 指向新目录时，`read_local_metadata()` 曾回退到 cwd 的 `metadata.json`，导致在归档 A 里给空目录 B 首次归档会误继承 A 的 uid/author/reads；现在只有完全不传 `--root` 时才允许 cwd 兜底。
21. **生成物会悄悄膨胀，要能看见体积**。`变更日志.md` 原本每轮都追加一段「无新增或改动」；`--accept-shrink` 缩水时同一份旧正文会同时写成 `.md` 与 `.before-delete.md` 两份。现在无变更不写日志、缩水只留一份语义化快照，并在 `--verify` 末尾按类别打印磁盘占用与最大的 3 个文件。实测 33 篇归档 38.96 MB 里 **36.85 MB 是 21 张配图**（单张最大 10.69 MB），文字全文仅 1.29 MB、阅读册 0.7 MB——要减体积先处理图片，不要误删原文。配图压缩是有损决策，交给使用者自己定；脚本不自动删也不自动压。
22. **首次归档抓不到正文时不能只跳过写盘**。若该篇仍留在 `meta_all`，`metadata.json` / `目录.csv` 有它而 `index.html` / `articles/` 没有，`--verify` 会连报数量与 ID 集合不一致。现在把这类篇目从本轮索引剔除、记【跳过】，下次 `--missing-only` 自动补抓。另外 `--missing-only` 复用分支曾把 `local_snapshot_reason` 洗掉、让「仅本地存档」悄悄变回「正常」，现由 `STATE_FIELDS` 继承修复；`remote_missing` 不进继承清单，否则永远清不掉。

24. **数字溯源的四个归一化边界坑（批量写摘要时集中暴露）**。33 篇摘要一次复查报 12 条「❌ 未找到」，逐条核实全是**摘要数字正确、归一化误报**，改摘要反而会改坏：① **全角逗号**：`FULL2HALF` 把「2763，0.382」的中文逗号转成半角，被 `NUM_PAT=\d[\d,]*` 当千分位吞成「27630.382」，凭空造数——全角逗号不映射到半角逗号。② **点分日期**：雪球作者用 `2024.9.24` / `2015.6.5` 标行情日期，原日期正则只认 `-/年`，被当行情数字；用严格限定 `19xx/20xx` 开头的 `DOT_DATE_RE` 在删空格**之前**剥离（尾部边界用 `(?<![0-9.])`/`(?![0-9.])`，因为 `2024.9起` 后接中文时 `\b` 不成立）。③ **跨行粘连**：`norm_digits` 的 `(?<=\d)\s+(?=[\d%])` 会把行末「2.64」与下一行章节号「5.」粘成「2.645」，改成只删同行 `[ \t]+`。④ **「年M月+点位」被误吃**：日期正则第三段 `(?:[-/月]\d{1,2}日?)?` 会把「2000年3月5132点」吃成「2000年3月51」只剩「32点」——把「月」分支限定为必须带「日」字：`(?:[-/.]\d{1,2}|月\d{1,2}日)?`。**教训**：遇到「未找到」先回原文看摘要数字是否真的抄错，别急着改摘要；归一化规则要按实际语料逐个验证，且每次改动都跑全库审计 + 负向用例（抄错值必须仍报 none）+ 既有基线篇目的数字数保持不变。
25. **基线不只是「检测过期」，更是「幂等 / 省 token」的依据；`--stamp` 不能无条件盖章**。摘要由大模型逐篇读全文写成，脚本本身是纯本地代码、不调用模型，token 只花在把全文读进上下文这一步。因此每轮加工前必须先跑 `--pending-summaries`，用 `source-md5` 把文章分成「需处理 / 可跳过」，基线一致的篇目一律不重读、不重写。早期 `--check-summaries --stamp` 无条件用当前正文 md5 覆盖基线：原文改了却没重读全文，跑一次 `--stamp` 就把「摘要可能过期」硬错误抹平，基线形同虚设，下轮还会误判成「可跳过」。现在基线不一致时拒绝更新并判失败，只有显式 `--accept-edits` 才放行；首次建立基线或基线一致时普通 `--stamp` 行为不变。清单只打印、不落盘，避免又多一份可再生产物；同理它必须进 `validate_options()` 的互斥检查，否则一个只读参数会走到全量写盘。

## 交付前校验

| 检查 | 方法 |
|---|---|
| 文件数量与 ID 集合 | `metadata` / `*.md` / `*.source.html` 三者 ID 完全一致 |
| 正文纯净度 | 正文文件查「【归档说明】」「归档补图」；阅读册另查 `undefined`、`<template`、`xqimg-local://`、未替换模板占位符 |
| 图片有效性 | 所有 `images/...` 引用存在；**被引用**的图片 md5 无重复组（孤儿图只提示，不判失败） |
| 阅读册 | 无 `undefined`、无 `<template`、无未替换占位符；目录项数 = 正文 section 数 |
| 离线可用 | `chrome --headless=new --host-resolver-rules="MAP * ~NOTFOUND" --dump-dom file:///<index.html>`，检查运行后 DOM 是否仍含正文 |
| 视觉 | `--screenshot` 后目视；`node --check` 校验内联 JS |
| CSV | 行数等于文章数；`--reads-file` 注入的阅读量在多次增量后仍在 |
| 元数据完整性 | `source` / `fetched_at` / `body_chars` / `topic` 齐全；`--verify` 会提示缺失并建议全量同步补齐（`images` 是可选统计字段，缺失不判问题） |
| 身份一致 | `metadata.json` 的 `uid` / `author` 与实际作者一致；不带 `--uid` 跑增量应能自动恢复，不会抓错人 |

| 划重点摘要 | 有 `summaries/<ID>.md` 的文章，阅读册里 `.highlight` 数量与摘要文件数一致；默认激活的是带 ★ 的那篇 |
| 开关生效 | 注入脚本勾选 `#only-summary`，`getComputedStyle(.doc.active .article-body).display` 应由 `block` 变 `none` |
| 总结复查 | `--check-summaries --stamp` 无硬错误；报告里没有「❌ 未找到」；`--verify` 显示摘要复查 0 硬错误 |
| 严格门禁 | 批量交付时加跑 `--check-summaries --strict`，任何待复核项一律判失败 |
| 基线新鲜度 | 摘要里的 `source-md5` 与当前正文一致；`--rebuild` 后必须重新核对并 `--stamp` |
| 增量摘要 | `--pending-summaries` 把基线一致篇目列为「可跳过」且**不写任何文件**；正文改一个字后该篇转为「原文已变」，其余篇目仍可跳过 |
| 数字归一化边界 | 点分日期（`2024.9.24`）、全角逗号并列数字（`2763，0.382`）、行末数字+章节号、中文日期+点位（`2000年3月5132点`）都不应产生「❌ 未找到」；抄错的数字（如 `29.9`）仍必须报 none |
| 基线防手滑 | 正文改动后 `--check-summaries --stamp` 退出码 1、摘要里的 md5 未变、报告写明未更新；加 `--accept-edits` 后基线才更新 |
| 删文 / 占位符保护 | 模拟「删 1 篇 + 新增 1 篇」后条目数不减少；模拟 288 字占位说明与「该内容已被删除」模板，本地 md 正文逐字不变；`--rebuild` 正文文字有变化时生成 `.pre-rebuild.md`；`--verify` 仍全通过 |
| 参数互斥 | `--stamp` 单独用、两个检查模式并存、`--missing-only`+`--rebuild` 都应退出码 2 并给出清晰报错，不能静默进入全量抓取 |
| 体积可见 | `--verify` 末尾按类别打印 MB 占用与最大 3 个文件；据此处置大图，不误删 `articles/` |
| 状态可见 | `目录.csv` 有「线上状态」列；阅读册对应篇显示「⚠ 仅本地存档」；`--verify` 列出仅本地快照篇数 |
| 无绝对字数误伤 | 约 150 字合法短文首次归档能写入且 `--verify` 通过；同文重抓不会生成 `shrink_note` |

## 阅读册加工层（划重点摘要）

- **加工视图必须改生成脚本，不能手改 `index.html`**：阅读册每次同步都重建，手工塞进去的卡片会在下一次 `--missing-only` 后消失。正确做法是让脚本读 `summaries/<ID>.md` 并渲染，md 成为唯一数据源。
- **Markdown 转换器要覆盖表格和列表**：通用 `md_to_html()` 只处理标题/段落/图片，直接拿来渲染摘要会把 `| 维度 | 状态 |` 变成竖线文本。摘要专用转换器需支持表格分隔行、连续引用块、有序/无序列表。
- **CSS 优先级陷阱**：阅读册已有 `#reader p`、`#reader h4`、`#reader strong` 等 id 级规则，普通 `.highlight p` 覆盖不了；摘要卡样式一律写成 `#reader .highlight ...`。
- **默认选中项要跟着新功能走**：阅读册原本默认打开最新一篇，若摘要在较早文章上，用户打开后第一眼看不到卡片。改为优先激活带 ★ 的目录项。
- **开关类交互用计算样式验证**：截图看不出 `display:none` 是否真的生效，注入脚本读 `getComputedStyle()` 写进 DOM 再 `--dump-dom` 更可靠。
- **改完 md 必须重建阅读册**：`index.html` 是静态快照，不会自动跟着 `summaries/` 变。复查会抽查卡片里的数字，缺了就报「未重建」，跑一次 `--missing-only` 即可；改完后再跑复查确认。
- **复查报告要能回溯**：每个数字都要给出原文上下文片段，让人不打开全文也能判断口径是否一致；否则「未命中」只是一个无法行动的告警。

## 合规与数据边界

- 著作权归原作者；仅个人研究存档，保留作者与原文链接，禁止公开分发或再发布。
- 只抓公开可见内容，不绕过登录、付费、权限或反爬机制；保持低频。
- 文中行情数字、观点均为作者个人整理，属**非一手来源**；阅读册与台账必须标注「需核实原文」，不作数据背书。
- 图片中的文字未 OCR，全文搜索覆盖不到；如需检索图内内容要单独处理。
